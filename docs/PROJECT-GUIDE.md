## 1. 项目是什么（30 秒认知）

个人使用的《原神》探索度记录网页应用，部署在腾讯云 **EdgeOne Pages**（免费、含国内节点，访问快）。

- 网页上按地区/成就章节展示探索进度，表格里直接录入"已搜集"数量，自动算探索度。
- 默认**只读**：其他人打开只能看；输入密码解锁后可以录入/改描述，改动自动存云端。
- 已搜集数据来自原神账号 **UID 212114083** 的游戏内成就面板；目标数量以 B 站攻略博主「你的影月月」为准（详见 README「数据口径」）。

**一句话心智模型——两类数据，两种改法：**

| 数据 | 是什么 | 放在哪 | 怎么改 |
|---|---|---|---|
| **target** | 目标数量（宝箱/挑战/仙灵/雷灵/幻写灵的总数） | `public/data/games.json`，**静态文件，随部署发布** | 改文件 → **重新部署**（改代码的方式） |
| **done** | 已搜集数量（你的游戏进度） | **云端 Blob**（EdgeOne 存储），运行时数据 | 网页解锁直接编辑 / 导入 JSON → **立即生效，不需要部署** |

> **最容易踩的误区**：重新部署只更新静态文件和代码，**不会碰云端已存的进度**。
> 所以"改 done 靠重新部署"是不成立的——done 的正确改法是网页编辑或导入。

## 2. 数据从哪来、存在哪（逻辑核心）

```
┌─ 目标数 target（固定值，写死在项目里）
│    来源：B站「你的影月月」全收集攻略（成就「总计」口径，截至 7.1）
│    存放：public/data/games.json ── 随构建打进 dist/ ── 重新部署更新
│
┌─ 已搜集 done（运行时数据，唯一经常变的东西）
│    来源：原神账号 UID 212114083 游戏内成就面板「总计」
│    存放：EdgeOne Blob（key: progress），首次为空时回退 public/data/progress.json（种子）
│    写入：网页解锁录入 → 1.2 秒防抖 → PUT /api/progress → 存进 Blob
│
└─ 描述 note（可选的备注）
     来源：你在展开行里写的文字
     存放：随 done 一起存进同一个 Blob 对象
```

服务端（`functions/api/`，文件即路由）一共四个接口：

| 接口 | 作用 | 权限 |
|---|---|---|
| `POST /api/auth` | 校验编辑密码 | 无（密码比对服务端环境变量 `EDIT_PASSWORD`） |
| `GET /api/progress` | 读云端进度（空则返回 `exists:false`） | 任何人 |
| `PUT /api/progress` | 写云端进度；**写前自动备份旧版到 `progress.prev`** | 需 `x-edit-password` |
| `POST /api/progress/restore` | 用 `progress.prev` 覆盖当前进度 | 需 `x-edit-password` |

完整数据流：

```
浏览器（Vue SPA）
 ├─ /data/games.json     固定值（目标数）——静态文件，随部署更新
 ├─ GET  /api/progress   读云端进度（Blob；为空时前端回退种子 progress.json）
 ├─ PUT  /api/progress   写进度（需密码；写前备份旧版 → progress.prev）
 ├─ POST /api/auth       校验密码（环境变量 EDIT_PASSWORD）
 └─ POST /api/progress/restore  从云端备份恢复
```

## 3. 本地开发与线上生产的区别

| 环境 | 用什么 | 进度数据从哪来 | 编辑会发生什么 |
|---|---|---|---|
| 本地 `yarn dev` | Vite 开发服务器（:5173） | 读静态 `public/data/progress.json` | 只改内存，**不落盘**（刷新就丢）；密码用 `.env.development` 的 `VITE_DEV_PASSWORD` |
| 本地 `yarn build` + `yarn preview` | 构建产物（:4173） | 同上（静态种子） | 同上 |
| 线上 EdgeOne | 部署后的 SPA + Functions | **读云端 Blob** | 防抖自动保存到云端，刷新/换设备都在 |

> 前端自动判断：构建产物（`import.meta.env.PROD`）走 API；本地 dev 默认走静态。
> 想在本机联调 Functions/Blob，用 EdgeOne CLI（`edgeone pages dev`）或把 `VITE_API_BASE` 指向本地 Java 学习副本（见 `java-backend/README.md`）。

## 4. 完整使用顺序（从第一次到日常）

### 4.1 首次运行（本地）
```powershell
cd D:\07-Code\Projects\MiYouExplorationLevel
yarn install     # 装依赖（用 yarn，见 package.json）
yarn dev         # 打开 http://localhost:5173
```
开发模式解锁密码见 `.env.development` 的 `VITE_DEV_PASSWORD`。

### 4.2 日常查看（线上）
打开线上网址 → 页面即只读展示全部地区探索度 → 点地区卡片进表格看明细。**什么都不用做，无需登录。**

### 4.3 日常录入 / 修改已搜集数（最常用）
1. 右上角「解锁编辑」→ 输入编辑密码（生产密码在 EdgeOne 控制台环境变量 `EDIT_PASSWORD`）。
2. 点地区卡片进入表格。
3. 在「已搜集 / 已完成」列录入数字（输入即更新探索度）。
4. 停手约 1.2 秒后自动保存，右上角状态条显示「已保存到云端」；失败会显示原因并可「重试保存」。
5. 同一浏览器会话内保持解锁；点「锁定」恢复只读。

### 4.4 写/改描述备注
表格每行最左侧 ▸ 展开 → 编辑模式下是输入框，只读模式下只展示。

### 4.5 备份（建议每大版本做一次）
- **导出**：解锁状态下，总览页「导出 progress.json」→ 下载一份当前云端进度的 JSON。
- **提交到 Git**：把导出的文件覆盖 `public/data/progress.json` 后 commit/push，作为长期存档。
- **云端自动备份**：每次保存前，服务端自动把旧版存到 `progress.prev`（单份轮换，无版本历史）——这是短期的兜底，Git 存档才是长期可靠的。

### 4.6 恢复进度
两个来源，按场景选：
| 场景 | 用哪个 |
|---|---|
| 刚误改了一两处 | 解锁 → 编辑栏「从备份恢复」→ 恢复到**上一次保存前**（云端 `progress.prev`） |
| 想回到更早的版本 / 批量覆盖 | 解锁 → 总览页「导入 JSON」→ 选择备份文件 → 覆盖云端 |

### 4.7 改目标数 target（不常发生）
1. 编辑 `public/data/games.json`（target 数值、描述等）。
2. 本地验证：`yarn test`（单元测试）+ `yarn build`。
3. `git commit` + `git push` → 触发 EdgeOne 自动构建部署。
4. 线上刷新即可看到新 target。

> 目标数的来源口径（影月月攻略、版本差异、重合计数说明）都写在各章节的 `desc` 里，改前先读。

### 4.8 部署（代码推上去就自动发布）
1. 改动提交并 push 到 Git 远端仓库。
2. EdgeOne Pages 控制台关联的仓库检测到 push → 按 `edgeone.json`（构建 `yarn build`、输出 `dist`）自动构建发布。
3. 首次建项目/换域名时在控制台配一次环境变量 `EDIT_PASSWORD`（保存后需重新部署一次生效）。
4. Blob 存储零配置，无需在控制台开通。

## 5. 关键逻辑澄清（易混点）

1. **重新部署 ≠ 改 done**：部署只更新静态文件和代码；云端 Blob 的进度数据不受影响。改 done 的正确路径是网页编辑或导入。
2. **本地 progress.json 不是线上数据**：它只是种子（云端首次为空时回退用）。云端有数据后，线上永远读云端，改本地种子文件对线上无效。
3. **密码不在前端**：生产密码只存在 EdgeOne 环境变量 `EDIT_PASSWORD`，前端代码/文件里没有；忘记密码在控制台改环境变量再重新部署即可。
4. **导入会覆盖整个云端进度**：导入成功后内存立即替换并自动 PUT 云端。导入前最好先导出当前进度留档。
5. **探索度怎么算**：地区探索度 = 各分项「已搜集/目标」比例的平均值；`target=0` 的分项（如渊下宫雷灵、挪德仙灵）不参与计算，表格显示"—"且不可录入。
6. **target=0 的含义**：该章节没有这个分项（成就口径下确实为 0），不是没填。
7. **为什么保留导入/导出**：导出=备份（云端 Blob 无版本历史，Git 存档最可靠）；导入=恢复 + 批量修改的快捷通道（一次性覆盖多处数字，不用在网页一个个点）。

| 想做什么 | 操作 | 需要部署吗 |
|---|---|---|
| 查看进度 | 打开线上网站 | 否 |

| 写描述 | 展开行 ▸ | 否 |

| 改编辑密码 | EdgeOne 控制台改环境变量 → 重新部署 | 是 |

## 7. 常见问题

**Q：线上打开发现进度是 0？**
A：云端 Blob 为空时前端回退种子 `progress.json`。如果之前录入过，多半是云端数据没读到——确认网络后刷新；仍为 0 且确认录入过，用「从备份恢复」或导入最近导出的 JSON。

**Q：保存失败怎么办？**
A：看状态条错误原因：`密码已失效` → 重新解锁；`云端保存失败` → 点「重试保存」或稍后再试。

**Q：新版本（大版本更新）后 target 要不要改？**
A：要复核。原神每个大版本可能新增宝箱/挑战/仙灵，需按影月月新攻略更新 `games.json` 对应章节 target，再部署。已搜集数 done 不受影响（你游戏内新搜集的按 4.3 录入）。

**Q：以后想加星穹铁道/绝区零？**
A：数据模型已解耦。`games.json` 的 `games[]` 追加一个游戏对象即可；`progress.json` 按游戏/地区/章节分键存储，前端总览页会自动出现游戏切换标签。加游戏时注意各分项 id 命名一致（chest/challenge/seelie/thunder_spirit/phantasm）。
