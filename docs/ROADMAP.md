# 产品路线图：从"探索度记录"到"米游个人工具站"

> 更新日期：2026-10-20
> 本文件记录产品方向、功能全景与分期规划，供开发与复盘使用。
> 功能取舍以玩家价值、数据可得性/合规性、开发成本三者排序；**灰档（非官方接口抓取）不做**。

## 1. 定位与目标

本项目从"原神探索度记录"起家，中期目标是成为**米游玩家的个人工具站**：参考提瓦特小助手（原神）、星穹工坊小助手（崩铁）的信息架构，把探索度、角色图鉴、抽卡统计、练度与养成规划聚合到一个多游戏框架下。

- **探索度保持手动记录**（不做自动采集）——这是本站核心，也是与"工坊"类工具差异化的自有数据。
- **自动数据只接安全档**：官方导出的抽卡记录（authkey / 导出 URL）等被社区默许、无账号风控的数据。
- **练度类数据走本地档**：手动录入 / 文件导入 + 本地评分，无风控、可离线。
- **灰档不做**：通过非官方接口抓取玩家展柜/实时面板（账号风险 + 违反用户协议 + 接口不稳定）。

## 3. 分期规划（Now / Next / Later）

> 分期是**结果、依赖与学习顺序**的表达，不是功能日历；无真实排期承诺。

### Now · 一期：打通"抽卡分析"，验证工具站形态

- **目标结果**：用户能导入自己的抽卡记录并看到统计；工具站从"记录工具"扩展到"数据工具"。
- **当前问题**：站点只有探索度一个数据面，工具站定位缺乏第二个立得住的能力。
- **关键行动**：
  1. 抽卡记录导入：原神 authkey URL → 解析 → 存本地/云端 Blob（游客存 localStorage，主人存云）。
  2. 统计视图：常驻/UP/武器池、五星与四星计数、保底进度、抽取总数、欧非指数。
  3. UIGF（原神）/ SRGF（崩铁）格式导入导出，社区通用、可迁移。
  4. 崩铁角色图鉴数据源调研（类 Amber 的开源镜像；无则暂用静态数据文件）。
- **依赖**：抽卡解析实现（自研或参考 UIGF 生态）；崩铁数据源调研结果。
- **结果信号**：端到端"导入 → 统计可见"在本地与生产均可跑通。
- **退出条件**：抽卡导入链路可用且至少一游戏落地；统计口径与用户认知一致。
- **重排触发器**：官方收紧 authkey 导出机制 → 降级为"手动录入抽卡"（本地档）。

### Next · 二期：练度与养成（本地档），补齐"个人数据中心"

- **目标结果**：用户能维护角色练度并得到本地评分，能算出养成缺口。
- **当前问题**：练度是工坊类工具的核心吸引力，但自动抓取不可做，需以本地录入方式补位。
- **关键行动**：
  1. 练度录入模型：等级 / 天赋 / 武器 / 圣遗物（原神）或遗器（崩铁），复用图鉴角色 id 对齐。
  2. 本地评分算法：先定口径（词条数 / 主副词条权重），再实现；口径需用户确认。
  3. 复用现有 XLSX/JSON 导入导出设施，练度数据可迁移、可备份。
  4. 材料/培养规划：静态材料表 + 勾选 → 缺口清单。
  5. 抽卡模拟（纯前端，二期可选）。
- **依赖**：一期抽卡与图鉴数据模型稳定；评分口径确认。
- **结果信号**：练度可录入、可评分、可导出；规划能给出缺口与优先级。
- **退出条件**：录入 → 评分 → 导出闭环；评分规则不引起争议（或用户接受纯记录不评分）。
- **重排触发器**：用户对评分规则不满意 → 调整为纯记录、不做评分。

### Later · 三期：多游戏与聚合（探索）

- **目标结果**：≥2 款游戏完整可用，站点呈工具站形态。
- **当前问题**：一期/二期若只在原神验证，多游戏框架的价值未兑现。
- **关键行动**：
  1. 崩铁（及后续游戏）图鉴、抽卡、练度完整接入。
  2. 统一数据导出（UIGF/SRGF 兼容 + 全量备份）。
  3. 版本/卡池资讯静态订阅页。
  4. 分享/对比（游客社交性，低优先级，用户反馈后再定）。
- **依赖**：数据源可用性（米游社/官方 wiki 开放程度）；用户实际使用反馈。
- **结果信号**：用户在 2 个以上游戏中持续使用。
- **重排触发器**：官方接口政策变化、数据源关闭、用户诉求转向。

## 4. 明确不做（后置或拒绝）

| 事项 | 原因 |
| --- | --- |
| 展柜自动抓取 / 实时 UID 面板 | 非官方接口：账号风控、违反用户协议、接口不稳定（灰档） |
| 探索度自动采集 | 用户已确认不做；与"手动记录 + 查漏补缺"定位冲突 |
| 社区账号体系 / 多人协作编辑 | 超出个人工具站定位；游客数据本地化是安全边界 |

## 5. 风险与数据依赖

- **抽卡导出 URL（authkey）**：官方导出链接有时效（约 24h），需用户每次导入时提供；社区通行做法，相对安全但非官方承诺，接口可能变动。
- **图鉴数据源（Project Amber）**：第三方镜像，可能关闭或变动；数据文件由脚本生成可重跑，必要时切换数据源（数据文件含 source 元信息，已为此预留）。
- **评分口径**：练度评分为产品判断，不是官方数值；上线前需明确口径并允许用户调整。
