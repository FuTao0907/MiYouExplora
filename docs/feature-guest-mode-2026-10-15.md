# 功能方案：游客模式 · 批量编辑 · XLSX 导入导出 · Tour 引导

> 研发可执行方案。日期：2026-10-15。基于当前代码现状（Vue3 SPA + EdgeOne Functions/Blob 全栈）设计，未改动任何现有数据文件。
> 现状锚点：`src/api/data.js`（数据层）、`src/composables/useProgress.js`（状态）、`src/views/Overview.vue`（总览）、`src/views/RegionView.vue`（表格）、`functions/api/*`（服务端）。

---

## 1. 背景与目标

当前网站只有两种状态：只读（未解锁，其他人只能看）和主人编辑（解锁后写云端 Blob）。目标：

1. **游客模式**：任何进站者不解锁也能录入**自己的**游戏数据，用于自己查漏补缺；改动只存浏览器本地（localStorage），**绝不写云端**。
2. **主人数据作为参考**：主人的已搜集数（UID 212114083）以"提示文本"形式供游客对照，可开关。
3. **一键修改**：把所有可修改项聚拢成一个集中编辑面板，避免逐项、逐页修改。
4. **XLSX 导入导出**：导入/导出改为 WPS/Excel 可直接打开编辑的 `.xlsx` 表格（代替 JSON），不懂开发也能用。
5. **Tour 漫游式引导**：首次进入用气泡组件分步引导新用户了解功能。

## 2. 总体设计（模式与数据流）

### 2.1 两种使用模式

| 模式 | 进入方式 | 编辑写入目标 | 数据来源 |
|---|---|---|---|
| **游客模式** | 默认（未解锁） | **localStorage**（浏览器本地） | 本地有则本地；无则借用云端主人数据作初始显示 |
| **主人模式** | 输入密码解锁（现有逻辑） | **云端 Blob**（现状不变） | 云端 |

> 现状变更：未解锁状态从"纯只读"变为"游客可编辑（仅本地）"。**纯只读模式取消**——游客的编辑天然只影响他自己的浏览器，不影响其他任何人的数据。

### 2.2 数据三份，互不混淆

```
games.json（target 固定值，静态）── 所有人共用，只读展示
云端 Blob progress（主人的 done）── 主人解锁后编辑；游客只读借用
localStorage guest_progress（游客的 done）── 游客编辑；只属于该浏览器
```

### 2.3 核心机制：借用显示 + 增量存储 + 归属导出

- **借用显示**：游客本地无数据时，表格输入框**显示主人的已搜集数作为初始值**（用户拍板）。
- **增量存储**：游客一旦修改某个格子，该格子的值写入游客本地数据；**未改动的格子不落本地**，继续借用显示主人值。
- **归属导出（关键约束）**：游客导出/导入时，**数据只包含游客自己的本地数据**；借用显示的主人值**绝不进入游客的导出文件**，避免归属混淆。

数据读取优先级（游客视角）：
```
某格子的值 = 游客本地有该格 ? 游客本地值 : (参考开关开 ? 主人云端值 : 0)
```

## 3. 数据模型与存储

### 3.1 游客本地存储

- key：`miyou_guest_progress_v2`（localStorage，JSON 字符串）
- 结构：与现有 `progress.json` v2 完全一致（`{version, updated_at, regions:{...}}`），仅存游客**实际改动过的项**。
- 存储时机：游客编辑后防抖保存（沿用现有 1.2s 防抖机制，写入 localStorage 而非云端）。
- 跨游戏：key 保持单一，结构按游戏/地区/章节分键（数据模型已解耦，游客数据同构）。

### 3.2 状态层（useProgress.js）改造

| 现有字段 | 改造后 |
|---|---|
| `progress`（内存数据） | 拆出两个来源：`cloudProgress`（云端/种子）与 `guestProgress`（本地）；展示值由 `displayProgress` 计算 |
| `editable` | 语义保留：解锁=主人模式；未解锁=游客模式（可编辑但写本地） |
| `saveAreaItem / saveAreaNote` | 按模式分流：主人→PUT 云端；游客→写 localStorage |
| `saveState` | 游客模式显示"已保存到本机"；主人模式显示"已保存到云端" |
| `exportProgress / importProgress` | 按模式导出对应数据（见 4.4） |

### 3.3 参考开关

- 存 localStorage key：`miyou_show_reference`（`'1'/'0'`，默认 `'1'`）。
- 影响：游客未改动格子的显示值（借用主人值 or 0）；主人模式无意义（本人数据即云端），开关隐藏。

## 4. 功能规格

### 4.1 游客模式（RegionView.vue + useProgress.js）

- **输入框**：游客模式下**可编辑**（不再 disabled）；主人模式同现状。
- **归属标记**：游客模式下，借用主人值显示的格子加弱化样式 + 小标签「参考」，游客自己的值正常样式——一眼分清"哪些是我的、哪些是参考的"。
- **录入上限**：仍以该章节 target 为上限（现状逻辑不变）。
- **参考提示开关**：表格上方或编辑栏提供「显示参考（主人数据）」开关，控制借用显示。

### 4.2 一键修改：批量编辑面板（新组件 `BatchEditPanel.vue`）

- **入口**：总览页 + 地区详情页各一个「一键修改」按钮。
- **形式**：弹出集中面板（用户拍板），列出**全部地区 → 章节 → 分项**的输入框，可折叠按地区分组。
- **行为**：
  - 面板中的值 = 当前模式的展示值（游客含借用参考，主人为云端值）。
  - 游客模式下，面板底部提示"未修改的项保持参考/空，导出只含你改过的数据"。
  - 关闭面板时把**改动过的项**写入当前模式数据（游客本地 / 主人云端防抖）。
  - 支持「清除本机数据」（游客）：一键清空 localStorage 游客数据，回到纯借用显示。

### 4.3 XLSX 导入导出（data.js + 新工具 `src/utils/xlsx.js`）

- **依赖**：引入 `xlsx`（SheetJS），用 yarn 安装并在 package.json 标明。
- **表格结构（导出）**：
  - Sheet 名：`探索进度`。
  - 列：`地区 | 章节 | 分项 | 目标数 | 已搜集`（主人模式导出时"已搜集"=云端值；游客模式="本地值"，借用值**导出为空**，并追加一列`参考（主人已搜集）`供对照）。
  - 每行一个章节分项；地区/章节按现有顺序。
- **导入**：解析 `.xlsx`，按 地区→章节→分项 匹配 id 更新"已搜集"列；非法格式/找不到匹配行给出明确报错（如"第 N 行找不到对应章节，请勿改动表头与地区/章节名"）。
- **归属**：游客导入 → 覆盖游客本地数据（仅导入文件中的项）；主人导入 → 覆盖云端（现状 JSON 导入行为迁移到 XLSX）。
- **入口**：总览页现有"导出/导入"按钮改造；导出文件名 `探索进度.xlsx`。

### 4.4 Tour 漫游式引导（新组件 `TourGuide.vue`）

- **触发**：首次访问（localStorage 无 `miyou_tour_done`）自动弹出；提供「重播引导」入口（编辑栏/页脚小按钮）。
- **实现**：自研轻量气泡组件（无新依赖）：高亮目标元素 + 气泡说明 + 上一步/下一步/跳过。
- **步骤（5 步）**：
  1. 欢迎：这是什么站（个人探索度记录，人人都能用自己的数据查漏补缺）。
  2. 地区卡片：探索度怎么看。
  3. 表格录入：输入框直接改，游客数据只存本机、参考（主人数据）可开关。
  4. 一键修改：集中编辑面板入口。
  5. 导入导出：WPS/Excel 表格文件用法 + 数据归属说明。

## 6. 验收标准

| # | 场景 | 验收 |
|---|---|---|
| 1 | 游客首次打开（无本地数据） | 输入框显示主人云端值并带「参考」标记；开关关闭后显示 0 |
| 2 | 游客修改一个格子 | 值变游客本地数据；刷新页面后仍在；**云端数据不变** |
| 3 | 游客导出 | `.xlsx` 中"已搜集"只含游客本地值；借用参考值不出现（放"参考"列） |
| 4 | 游客导入 | 只更新游客本地数据；云端不变 |
| 5 | 主人解锁编辑 | 与现状一致：写云端、状态条"已保存到云端" |
| 6 | 一键修改 | 弹出面板列全部项；改动项正确写入当前模式；游客改动项与表格显示一致 |
| 7 | 清除本机数据 | 游客本地清空，回到借用显示 |
| 8 | Tour | 首次访问自动弹出 5 步；可跳过；有重播入口；再次访问不自动弹 |
| 9 | 回归 | `yarn test` 全绿；`yarn build` 通过；现有 JSON 导入导出路径保留（作为高级选项或移除需另行确认） |

## 8. 本期不做（明确后置）

- 多游客身份区分（无登录体系；localStorage 按浏览器天然隔离，同浏览器即同一游客）。
- 游客数据云同步/跨设备（如需要，属未来全栈扩展）。
- JSON 导入导出是否保留为高级选项：**待确认**（默认保留入口但弱化，避免混淆）。
- 多游戏（星穹铁道等）游客数据：结构已解耦，本期不单独开发。
