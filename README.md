# 米游探索度记录

个人使用的探索度记录网页应用，记录《原神》各地区及各子区域的探索进度。数据模型与游戏解耦，后续可扩展星穹铁道、绝区零等。

> **想快速上手 / 建立使用认知？先读 [`docs/PROJECT-GUIDE.md`](docs/PROJECT-GUIDE.md)**——它讲清楚了这个项目的使用顺序、数据流动和两条修改路径（target 随部署 / done 存云端），并有日常维护速查表。本文档是结构参考手册。

## 界面

* **主页面**：按地区（蒙德、璃月、稻妻、须弥…）显示探索度百分比与状态，点击地区卡片进入详情。

* **地区详情页**：一张表格，行为子区域，列为各分项的「总数 / 已完成（已搜集）」，直接在表格里录入。

* **编辑权限**：默认**只读模式**（其他人打开只能看，输入框与导出/导入均禁用）；右上角点「解锁编辑」输入密码后进入编辑模式，可录入、写描述、导出。同一浏览器会话内解锁状态保持，点「锁定」恢复只读。密码校验在**服务端**（生产环境为 EdgeOne 控制台设置的环境变量 `EDIT_PASSWORD`，不再下发到前端文件）；开发模式密码见 `.env.development` 的 `VITE_DEV_PASSWORD`。

* **云端自动保存**：编辑模式下录入/写描述后，约 1.2 秒防抖自动保存到云端（EdgeOne Blob），状态条显示「保存中… / 已保存到云端 / 保存失败」，失败可一键重试。无需手动导出替换重新部署。

* **展开行描述**：表格每行最左侧的 ▸ 按钮可展开该子区域的描述区，用于记录备注（如剩余宝箱位置、任务进度）；编辑模式下为输入框，只读模式下仅展示。

| 表头列          | 说明             |
| ------------ | -------------- |
| 子区域名称        | 该地区下的子区域       |
| 宝箱总数 / 已搜集   | 宝箱目标数量 / 已搜集数量 |
| 限时挑战总数 / 已完成 | 挑战目标数量 / 完成数量  |
| 仙灵总数 / 已完成   | 仙灵目标数量 / 完成数量（纳塔为「幻写灵」，见下） |

> 纳塔的探索分项为「幻写灵」（原神 5.0 起纳塔地区以幻写灵取代传统仙灵），games.json 中纳塔子区域的第三分项为 `phantasm / 幻写灵`，界面表头显示「幻写灵总数」。

## 探索度计算

地区探索度 = 各分项完成比例的平均值，**分母取地区目标（games.json 中 `region.targets` = 该地区各成就章节目标之和，对应游戏内成就系统的权威统计）**，分子取该地区全部章节录入的已搜集数量之和；target 为 0 的分项不参与计算。探索度由录入数据自动计算，不单独存储。

* 未开始：探索度 ≤ 0
* 已完成：探索度 ≥ 100
* 进行中：其余情况

## 技术栈（全栈）

* Vite 6 + Vue 3 前端（SPA）
* EdgeOne Pages Functions 服务端（`functions/` 目录，文件即路由）
* EdgeOne Blob 存储（`@edgeone/pages-blob`，零配置，写后即读）保存录入数据
* 依赖管理使用 yarn（见 package.json）
* **Java 学习副本**（`java-backend/`）：用 JDK HttpServer + Gson 在本地重写同一套 API，用于学习 Java 后端；生产仍用 EdgeOne JS 版，前端可切换联调（详见 `java-backend/README.md`）

## 本地开发

```
yarn install      # 安装依赖
yarn dev          # 开发服务器（默认 http://localhost:5173）
yarn build        # 构建生产产物到 dist/
yarn preview      # 本地预览构建产物（默认 http://localhost:4173）
```

开发模式（`yarn dev`）不依赖云端：进度数据读静态 `public/data/progress.json`，编辑保存在内存（不落盘），解锁密码用 `.env.development` 中的 `VITE_DEV_PASSWORD`。需要完整调试 Functions/Blob 时，可用 EdgeOne CLI（`npm install -g edgeone`，`edgeone pages init/link/dev`）。

## 单元测试

两条测试线，覆盖项目核心契约：

| 范围 | 框架 | 命令 | 覆盖 |
| --- | --- | --- | --- |
| 前端探索度逻辑 `src/utils/status.js` | Vitest | `yarn test` | `regionPercent`：空区域 / 无目标 / 单分项比例 / 多分项平均 / 超上限封顶 100 / 缺失数据按 0 / 四舍五入；`getStatus` 未开始·进行中·已完成三分支 |
| Java 学习副本 `java-backend/` | JUnit 5（console-standalone，零构建工具） | `pwsh -File java-backend\scripts\test.ps1` | `AuthService` 密码校验（默认值 / 显式密码 / 空输入）、`ProgressStore` 读写一致 / 写前备份 / 恢复 / 状态轨迹、四个 handler 的状态码契约（200 / 204 / 401 / 400 / 404 / 405） |

* 两个脚本都会先编译再运行（Java 脚本编译 main + test 到 `out/`，再自动发现全部测试）。
* **Java 测试务必用 PowerShell 7（`pwsh`）运行**——脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 会按 ANSI 误读中文导致语法错误。
* 依赖环境变量的用例（默认密码路径）用 JUnit `Assumptions` 守卫：当前进程设置了 `EDIT_PASSWORD` 时自动跳过，不会误报失败。
* 历史缺陷：测试曾发现两个真实缺陷——`AuthHandler` / `ProgressPutHandler` 收到非法 JSON 时 Gson 抛 `JsonSyntaxException` 未被捕获，异常冒泡成 500，违反「解析失败 → 401 / 400」的契约。已在两个 handler 补 try/catch 修复，并各加一条回归测试（`非法JSON按拒绝处理` / `密码正确但body非法返回400`）。


## 架构与数据流

```
浏览器（Vue SPA）
 ├─ /data/games.json     固定值（游戏/地区/子区域/目标数）——静态文件
 ├─ GET  /api/progress   读取云端进度（EdgeOne Blob；首次为空时前端回退种子数据）
 ├─ PUT  /api/progress   写入进度（需 x-edit-password 头；写前自动备份旧版到 progress.prev）
 ├─ POST /api/auth       校验编辑密码（环境变量 EDIT_PASSWORD）
 └─ POST /api/progress/restore  从云端备份恢复
```

数据模型与游戏解耦：`games.json` 的 `games[]` 数组可追加新游戏（星穹铁道/绝区零等），`progress.json` 按地区/子区域分键存储，未来加游戏或功能无需改架构。

## 数据文件

| 文件            | 位置                          | 说明                                    |
| ------------- | --------------------------- | ------------------------------------- |
| games.json    | `public/data/games.json`    | 固定值：游戏、地区、子区域、分项及目标数量（写死在项目中，改后需重新部署） |
| progress.json | `public/data/progress.json` | 种子/备份数据（生产环境首次部署时云端为空，前端回退此文件；此后以云端为准，导出可作备份） |
| images/       | `public/images/`            | 各地区实景图（个人使用；`games.json` 中 `region.image` 引用，如 `/images/mondstadt.jpg`） |
| functions/    | `functions/api/...`         | 服务端函数（路由见上「架构与数据流」） |

## 数据口径（重要）

**结构**：`areas` 即游戏内**探索成就章节**（每地区 3-4 章，共 26 章），章节名与成就合集一一对应（如稻妻「雷与永恒的群岛·其之一/其二」「雾海纪行」「白昼之光」）。**数量核对以 B 站攻略博主「你的影月月」的全收集攻略为主**（其视频标题与攻略均以游戏内成就「总计」为口径），并参考米游社《到7.1版本为止，目前可正常获得的原神全宝箱成就数》等汇总帖交叉核对；宝箱/仙灵/雷灵/幻写灵/挑战均为成就「总计」口径，版本差异以影月月攻略为准。已按影月月口径全量核对（2026-10-15）：26 章 target 全部一致。

| 地区 | 章节数 | 宝箱 | 限时挑战 | 仙灵/幻写灵 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 蒙德 | 3 | 975 | 54 | 86 | 城邦 519/17/51 + 雪山 234/-/32（雪山成就集无限时挑战分项）+ 魔山 222/37/3 |
| 璃月 | 3 | 1716 | 130 | 138 | 海港 1135/47/81 + 层岩 248/20/37 + 沉玉 333/63/20 |
| 稻妻 | 4 | 915 | 98 | 69 + 雷灵 68 | 其一 357/35/21/雷43、其二 204/29/6/雷19、鹤观 169/16/6/雷6、渊下宫 185/18/36 |
| 须弥 | 4 | 1475 | 160 | 156 | 雨林 575/45/54 + 沙漠其一 354/52/52 + 其二 290/37/27 + 佑灵 256/26/23 |
| 枫丹 | 4 | 945 | 144 | 75 | 泉舞 344/53/42、243/28/13、207/30/13 + 古海 151/33/7 |
| 纳塔 | 4 | 999 | 74 | 幻写灵 72 | 盟地 411/17/40、202/11/12 + 圣山 217/14/14 + 夏日 169/32/6 |
| 挪德卡莱 | 3 | 752 | 22 | 0 | 乐园 299/13、229/5 + 残月 224/4（无仙灵分项） |
| 至冬 | 1 | 345 | 31 | 13 | 圣都·其之一 |

* **稻妻雷灵**：成就「鸣草丛中的捕手」统计雷灵（其一 43、其二 19、鹤观 6），games.json 中稻妻分项含 `thunder_spirit/雷灵`；限时挑战各章均有（其一 35、其二 29、鹤观 16、渊下宫 18）。无该分项的章节（如渊下宫雷灵）target=0，表格显示"—"且不可录入。
* **target=0 的含义**：成就章节口径下每个分项都有确定数（要么有数要么真 0），`target=0` 表示该章节无此分项，录入上限即 0（不再回退地区目标）。
* **仙灵口径**：须弥雨林成就显示 53（存在计数 bug，按实际 54 记）；佑灵砾漠按 7.x 成就面板 23 记（公开帖截至 7.0 为 21）；古海狂诗按区域实际 7 记（成就「金宫引路人」门槛显示 6）；挪德卡莱无传统仙灵分项，记 0；纳塔第三分项为幻写灵（非仙灵）。
* **雪山无挑战分项**：「雪山上的来客」成就集不含限时挑战成就（蒙德「逐风的冒险家」明确排除龙脊雪山），故雪山不设挑战目标（区域约 16 个挑战点位不计入任何成就）。
* **版本注意**：成就面板每条目的「总计」显示的是**该账号已搜集数量**（如城邦「逐风的寻宝者」面板总计 483 = 已开启 483 个宝箱），games.json 的 target 是**攻略全宝箱/仙灵/挑战总数**（城邦宝箱 519）——录入时以游戏内面板「总计」作为已搜集数，target 保持攻略值；稻妻其之一做过限时活动会多 1 个宝箱（358）；纳塔夏日为 5.8 限时海岛（现仍可正常获取，计入成就数）。大版本更新后需复核。

## 使用流程（全栈：编辑即保存）

1. 打开线上应用，右上角「解锁编辑」输入密码（生产密码见 EdgeOne 控制台环境变量 `EDIT_PASSWORD`）。
2. 点击地区进入表格，在「已搜集 / 已完成」列录入数量（输入即实时更新探索度，约 1.2 秒后自动保存到云端）；▸ 展开行可写描述。
3. 保存状态显示在右上角状态条：保存中… / 已保存到云端 / 保存失败（可重试）。
4. 定期（如每大版本）点「导出 progress.json」下载存档，提交到 Git 仓库作为长期备份——云端 Blob 无版本历史，误改后可在编辑模式下「从备份恢复」（恢复到上一次保存前的版本），但 Git 存档仍是最可靠的兜底。

## 部署（EdgeOne Pages，腾讯云，免费）

> 项目已纳入 Git 版本控制（master 分支），`.gitignore` 已配置（`node_modules` / `dist` / `.env*` / `doc-fetch-resources` / `draft_*` 不入库；`.env.development` 里的开发密码只在本机 dev 生效）。

1. 代码推送到 Git 仓库；在腾讯云 EdgeOne Pages 控制台创建项目并关联该仓库，构建命令 `yarn build`，输出目录 `dist`，安装命令 `yarn install`（或直接使用仓库根 `edgeone.json`，平台自动读取）。
2. **设置环境变量**：控制台「项目设置 → 环境变量」添加 `EDIT_PASSWORD`（编辑密码，值需 ≤1000 字节），保存后**重新部署**一次使其生效。
3. **Blob 存储零配置**：`functions/` 内通过 `@edgeone/pages-blob` 的 `getStore('miyou-exploration')` 直接使用，无需在控制台开通/绑定。
4. 部署完成后访问分配的域名。EdgeOne 免费套餐含国内节点，访问速度优于 Cloudflare 免费版；免费额度（Edge Functions 300 万次/月、Blob 1GB）对本应用用量绰绰有余。

> 本地 `yarn dev` 走静态数据、生产走 API 的切换由 `import.meta.env.PROD` 自动判断，无需手动配置。
